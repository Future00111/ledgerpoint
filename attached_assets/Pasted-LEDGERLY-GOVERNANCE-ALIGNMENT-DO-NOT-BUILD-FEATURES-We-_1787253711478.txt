1. Ledgerly Manifesto
2. Product Principles
3. PRD/Product Scope
4. Technical Architecture
5. Master Backlog
6. Definition of Done

If a conflict is discovered:

DEFINITION OF COMPLETE

A feature is NOT complete merely because:
- a page exists
- a component renders
- an API exists
- a database table exists
- a CRUD operation works
- a test passes

A feature is complete only when it satisfies the applicable Definition of Done, including where relevant:

- end-to-end user workflow
- correct accounting effects
- correct VAT effects
- correct permissions
- company isolation
- auditability
- error handling
- loading states
- empty states
- responsive UX
- Ask accessibility
- automated tests
- browser verification
- Manifesto compliance.

ASK

The Manifesto states:

"Ask is the heart of Ledgerly."

Therefore, when implementing any major user-facing feature, consider:
- how Ask discovers it
- how Ask explains it
- how Ask navigates to it
- whether Ask can safely initiate the workflow
- what actions Ask may draft
- what actions require approval.

Do not force AI into workflows where deterministic rules are better.

ACCOUNTING

The Manifesto states:

"Ledgerly is accounting software first."

Therefore:

- accounting rules take precedence over AI
- financial calculations must be authoritative
- accounting records must be auditable
- automation must be transparent
- AI must never silently make financial decisions.

AI PRINCIPLES

AI must assist accounting rather than replace accounting principles.
