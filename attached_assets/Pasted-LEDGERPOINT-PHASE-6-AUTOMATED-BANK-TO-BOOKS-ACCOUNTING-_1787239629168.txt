LEDGERPOINT — PHASE 6
AUTOMATED BANK-TO-BOOKS ACCOUNTING WORKFLOW

IMPORTANT:
Phase 5 — AI Accountant: Intelligent Transaction & Bookkeeping Engine has now been completed.

Do NOT redesign or rebuild the Phase 5 AI Accountant.

Do NOT create another AI engine.

Do NOT create a second reconciliation system.

This phase must build on the existing Ledgerpoint architecture and connect the existing:

- Banking
- Bank transaction import
- Reconciliation
- Invoice matching
- Bills
- VAT Assistant
- AI Accountant
- AI review queue
- AI provider service
- audit trail
- company/tenant security
- permissions

The purpose of Phase 6 is to turn these components into a coherent automated bank-to-books workflow.

==================================================
1. PRODUCT OBJECTIVE
==================================================

When a bank statement or bank transaction is pulled into Ledgerpoint, the user should NOT have to manually analyse every transaction.

Ledgerpoint should automatically:

1. Import the transaction.
2. Analyse the transaction.
3. Find matching invoices/bills.
4. Identify possible multiple matches.
5. Identify partial payments.
6. Identify unexplained amounts.
7. Identify possible duplicates.
8. Suggest categorisation where no invoice/bill exists.
9. determine applicable VAT treatment through the existing deterministic VAT engine.
10. calculate confidence.
11. decide whether the item is:
    - Ready
    - Review Required
    - No Match
    - Partial Match
    - Possible Duplicate
    - VAT Review
12. Prepare the appropriate action.
13. Present the user with a clean approval/review queue.

The user's job should increasingly become:

"Review what Ledgerpoint could not confidently resolve."

rather than:

"Manually reconcile every bank transaction."

==================================================
2. IMPORTANT ACCOUNTING SAFETY RULE
==================================================

Automation does NOT mean uncontrolled automatic posting.

Ledgerpoint may automatically:

- analyse
- match
- rank
- classify
- prepare
- calculate
- explain

But it must respect existing approval rules before permanently changing accounting records.

High-confidence items should be presented as:

READY TO APPROVE

rather than silently posting them unless an existing company setting explicitly permits automatic reconciliation.

Do not introduce autonomous accounting posting without a clear existing approval mechanism.

==================================================
3. BANK IMPORT PIPELINE
==================================================

Find the existing bank statement/transaction import flow.

Extend it rather than replacing it.

The workflow should become:

BANK IMPORT
    ↓
TRANSACTION NORMALISATION
    ↓
DUPLICATE CHECK
    ↓
DETERMINISTIC MATCHING
    ↓
AI ANALYSIS IF REQUIRED
    ↓
VAT ANALYSIS
    ↓
CONFIDENCE CALCULATION
    ↓
DECISION STATE
    ↓
RECONCILIATION / REVIEW QUEUE
    ↓
USER APPROVAL WHERE REQUIRED
    ↓
ACCOUNTING RECORD UPDATE
    ↓
AUDIT TRAIL

This should happen automatically after import.

==================================================
4. BATCH ANALYSIS
==================================================

When a statement containing multiple transactions is imported, Ledgerpoint should analyse the entire batch.

Example:

Statement imported:
24 transactions

Ledgerpoint should display something like:

BANK STATEMENT ANALYSIS COMPLETE

24 transactions analysed

18 Ready
3 Review required
2 No match
1 Possible duplicate

Potential invoice value:
£18,420

Unexplained receipts:
£2,750

Total requiring attention:
6

Do not hard-code any numbers.

All values must come from actual company data.

==================================================
5. BATCH PROGRESS
==================================================

During analysis, show useful progress.

Example:

Analysing bank statement...

24 / 24 transactions analysed

Then:

Analysis complete.

Avoid leaving the user wondering whether Ledgerpoint is still processing.

If processing is asynchronous, use the existing backend/job architecture if available.

Do not block the browser unnecessarily.

==================================================
6. AUTOMATIC MATCHING
==================================================

Use the Phase 5 matching engine.

For every transaction:

Find candidate invoices/bills.

Use deterministic signals first:

- exact amount
- reference
- invoice number
- customer/supplier
- date
- due date
- description
- historical relationships

Use AI semantic reasoning only where useful.

Do not call the LLM for obvious exact matches unnecessarily.

Do not create duplicate income/expense entries.

==================================================
15. VAT INTEGRATION
==================================================

Continue using the Phase 4 deterministic VAT engine.

Do not create another VAT calculation engine.

For each transaction where VAT treatment is relevant:

Request the authoritative VAT treatment from the existing VAT service.

If sufficient evidence exists:

VAT treatment ready.

If insufficient evidence:

VAT REVIEW REQUIRED.

Never allow the LLM to become the authoritative VAT calculator.

26. RE-ANALYSIS
==================================================

Provide:

when appropriate.

If the user adds an invoice after the bank transaction was originally analysed:

Ledgerpoint should be able to re-run the transaction.

Example:

Yesterday:
£5,000 receipt
No match

Today:
INV-456 £5,000 created

Re-run analysis:

Exact match found.

The old analysis must remain auditable.

The new analysis becomes the current recommendation.
