1. CI PLATFORM BOUNDARY

- network boundary;

- Node/package/runtime requirements;
- timeout/resource requirements;
- concurrency behavior.

If a specific CI provider must be selected, identify the proposed provider
and why, but do not create/configure it yet.

2. TRUST-PLANE SEPARATION

Define three explicit planes:

A. CI ADMIN/BOOTSTRAP PLANE
- controls the PostgreSQL service container;
- performs database/role/schema bootstrap;
- may use the container-local postgres administrator;
- never exposes admin credentials to Ledgerly application/test child
  processes.

B. TEST PLANE
- connects only as ledgerly_api;
- runs canonical/TR-01 tests;
- cannot create databases/roles;
- cannot weaken RS-01 protections.

C. NORMAL REPLIT DEVELOPMENT PLANE
- remains heliumdb;
- remains ledgerly_api;
- is never the canonical test target.

3. POSTGRESQL PINNING

- major/minor pinning policy;
- image digest policy if appropriate;
- upgrade review procedure;
- compatibility evidence required before changing PostgreSQL version.

4. BOOTSTRAP CONTRACT

Define the exact bootstrap sequence from an empty PostgreSQL service.

repository sources.

- creation/configuration of ledgerly_api;

- SC-01 schema requirements;
- RS-01 SQL overlay;
- ownership transfer;
- ENABLE ALWAYS protections;
- required constraints/indexes;
- private run-control metadata;
- final bootstrap verification.

Identify the exact repository files/scripts that are authoritative.

Do not duplicate schema definitions unnecessarily.

5. CREDENTIAL MODEL

The PostgreSQL service exists only for the CI job.

Define how:

- a random per-run ledgerly_api password is generated;
- the admin password remains confined to bootstrap;
- the ledgerly_api URL is constructed;
- LEDGERLY_CANONICAL_TEST_DATABASE_URL is supplied;
- credentials are masked from logs;
- child environments receive only what they require;
- credentials cease to exist when the job/container ends.

No long-lived PostgreSQL administrator secret should be required.
