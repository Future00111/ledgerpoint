TASK
==================================================

Proposed implementation sub-task:

#44-RS-01 — Development Database Role Separation

Purpose:

Make the Ledgerly development API run as a dedicated non-superuser database
principal so the already-approved #44 persistence-level immutability controls
can actually be enforced.

This is a technical sub-task of #44.

It is NOT a new governance decision.

Do NOT create DEC-23.

==================================================
SELECTED DEVELOPMENT ROLE MODEL
==================================================

The approval package must select this concrete model:

1. ADMINISTRATIVE DATABASE PRINCIPAL

Used only for controlled administrative operations such as:

- CREATE ROLE
- ALTER ROLE
- ownership transfer
- schema DDL
- privilege management

It must NOT be used by the running API.

2. ledgerly_canonical_owner

Attributes:

- NOLOGIN
- NON-SUPERUSER
- owns the protected canonical accounting tables
- owns approved immutability trigger functions
- cannot be used as the API runtime identity

3. ledgerly_api

Attributes:

- LOGIN
- NON-SUPERUSER
- NOCREATEROLE
- NOCREATEDB
- NOREPLICATION
- no BYPASSRLS privilege
- must not own canonical tables
- must not be able to SET ROLE to ledgerly_canonical_owner
- must not be granted membership in ledgerly_canonical_owner
- must not be able to alter or disable canonical protection

EXACT PRIVILEGE DESIGN
==================================================

Define the exact minimum privileges ledgerly_api requires.

Review the current application and identify the privileges it genuinely needs.

At minimum classify:

- CONNECT on database
- USAGE on schema
- SELECT
- INSERT
- UPDATE
- DELETE
- sequence USAGE/SELECT
- function EXECUTE

Separate:

A. ordinary application tables;
B. canonical accounting tables;
C. accounting posting effects;
D. canonical audit/relations;
E. migration/schema administration.

For canonical protected tables, preserve the #44 rules.

ledgerly_api must not receive broad UPDATE/DELETE/TRUNCATE authority on immutable
canonical records.

Do NOT give ledgerly_api ownership-level privileges.

Do NOT grant ALL PRIVILEGES as a shortcut.
